## Task

Produce one bundle absorbing outline `${OUTLINE_ID}`. The bundle should:

- Create entities the outline calls for that don't already exist in the
  live graph (`create-entity` ops, with outbound edges in the same op).
- Modify descriptions on existing entities where the outline updates
  them (`modify-block` ops, one per block — never bundle multiple
  blocks into one op).
- Add or remove edges where the outline rewires relationships
  (`add-edge` / `remove-edge` ops).
- Always end with an `obsolete-outline` op on the outline entity itself
  (`Outline:${OUTLINE_ID}`), reasoning briefly why the outline is now
  fully absorbed. Jan does not accept this op directly — ingest stores
  it; auto-archival fires once all other entities are accepted.

Constraints:

- Stay strictly within what the outline + live-entity context support.
  No hallucinated dates, ranks, locations, or relationships.
- Match Jan's editorial voice: factual, Norwegian where the entity is
  Norwegian, citation-friendly. Mark inferred facts as inferred in the
  prose ("antatt", "trolig", "iflg. <kilde>").
- Do not duplicate content already present in `descriptions[]` on a
  live entity — if the outline restates known facts, skip the op.
- Edge targets must resolve to either a live entity (in
  `LIVE_ENTITIES_JSON`) or another entity being created in this same
  bundle. Don't reference entities you neither create nor see live.
- Slugs must match `/^[a-z0-9-]+$/`. Entity IDs are `<Kind>:<slug>`.
- `blockPath` must match `section.<slug>.block.<key>`.

## Skip path

If the outline has nothing left to absorb (already fully absorbed in a
prior bundle, or is purely a placeholder), write:

```json
{ "skip": true, "reason": "<one sentence>" }
```

instead of a bundle. The workflow comments + closes the issue without
ingesting.
